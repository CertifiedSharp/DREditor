## Policy Introduction
### We welcome contributions that do not need much work
We encourage contributions and while we try do do it, our existing contributors have limited time to mentor or guide new contributors. When a contribution needs changes, existing contributors will usually make any necessary changes themselves rather than working with the original contributor to make the changes. However, we strive to give primary credit to the original contributor whenever possible. We especially encourage contributions that make it easier for new contributors to become productive without direct mentoring, such as documentation, tutorials, refactoring, tests, and similar.

## Assigning Credit
**Our overall philosophy of giving credit is**: We give credit by name to all tangible contributors. When submitting a contribution, we expect contributors to include accurate information about who contributed to the work.

**How we give credit**: 

- **For code contributions**: We add a line to the top of the code file as an Author Like: “Author:” or “Original/Edited/Reworked Author:” or if code is completely reworked with permission from the original contributor, it is up to the reworked contributor whether to give credit to the original contributor if the code file does not remotely resemble the original authors work. However not doing so is usually frowned upon.
- **For code documentation for the API**:  Only pages in bulk can be submitted. You must request which code file(s) you wish to write documentation for. Please keep in mind that there are some scripts in which the code authors would like to do themselves, so your request may be denied. If accepted you'll be credited on the API website or through a Documentation Authors page on the website. By contributing to the API, you agree that the full credit and control of the code is to the authors of the code file.
- **If you're making tutorials**: Contact the project maintainer. Credit yourself however you wish and consider being apart of our public [**Resources.**](https://dreditor.net/docs/resources.html)

**We reserve the right to change how we give credit when following this policy seems detrimental to our project. Some examples of when we may not follow our credit guidelines**:

- Someone requests credit to a name that is obscene or harmful
- Someone is spamming multiple projects with useless changes
- We don't want to be associated with the contributor
- A contributor is not following our code of conduct or otherwise harming our project

## Specific instructions for contributors who want credit
Please make it easy for us to accept and credit your contribution! Here are the steps to take to get the most credit for your work:

- Agree to the CLA. (Contact the project maintainer to be sent one)
- Respond to requests for changes within 7-30 days.
- Cooperate in good faith with our requests for changes.
- If you do not want to make changes, please tell us as soon as possible.

If for some reasons you can’t or won’t make necessary changes to your contribution, we will reject your contribution and take no further action.

## Correcting mistakes in credit
Sometimes we make a mistake in how we give credit. In this project, we will correct any mistakes in how credit is given, usually by updating the list of authors on the website and including the credit within the repository with a commit so it will be present in the next update.

## Reporting problems with contributions and credit
If you notice that this policy has not been followed properly, please contact the project maintainer or dreditortool@gmail.com and include any relevant information. They will review your report and take any action they deem appropriate, including but not limited to updating credit information, warning the person or organization who did not follow the policy, no longer accepting contributions from a particular source, updating the policy, or any other actions deemed necessary.

## Contributor names
From time to time, names change. Our policy for changing names associated with credit for this project is to contact a maintainer/lead and request the change. You may be asked to resign a CLA. Failure to do so will result in your request being denied.

Our convention for names associated with contributions is:

- Names are unique
- English Alphabet Only
- We accept any name a contributor is known by as long as a maintainer can verify your connection to the name using your signed CLA.
