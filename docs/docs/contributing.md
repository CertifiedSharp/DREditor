# Contributing to DREditor

Thank you for your interest in contributing to DREditor! We value community contributions and appreciate your help in making DREditor better. Please note that this information may be subject to change in the future!

## Types of Contributions We Accept

### ✅ We Encourage and Accept

- **Bug fixes and patches**: If you've found a bug and have a fix, we welcome your contribution. 
- **Security vulnerability reports**: Please report security issues responsibly by contacting the project maintainer.
- **Documentation improvements**: Help make our docs clearer and more comprehensive.
- **Testing and feedback**: Report issues, test new features, and provide feedback.
- **Small code improvements**: Performance optimizations, code cleanup, and minor enhancements

### ⚠️ Discuss First

- **Feature requests & Large changes**: Please open a request on the discord or contact the project maintainer. As we must ensure that requests and large changes will be overall worth the time spent into them. As we must ensure bug testing as to not obstruct active users development with their projects using DREditor. If your change or feature does not edit any actual code within the repository, consider making it a community plugin! We're happy to assist those wishing to do so. 

### ❌ Generally Not Accepted

- **Reworks of existing Code**: If it isn't broken don't fix it. Please leave reworks to the project maintainer or at least request it so the project maintainer can take care of it.
- **Large external feature contributions**: Features carry a long-term maintenance burden. To reduce burnout and maintain code quality, we typically implement major features internally. This allows us to ensure consistency with the overall architecture and maintain the high reliability that DREditor users depend on.
- **Breaking changes**: Changes that break backward compatibility require extensive discussion and depending on the circumstance will likely not be accepted.
- **Code that does not follow NDepend Rules**: In order to remove overall technical debt. The Project Maintainer Sweden has spent his own money on the technical software NDepend which helps maintain code health. You as a contributor are **not _required_** to have NDepend, however, if the project maintainer finds any NDepend Issues present, your contribution may be edited or sent back to you in order to correct this. For more information, please contact the project maintainer.
- **Code that does not follow code guidelines**: DREditor is intended to be used by users who **do not code** AND **people who are new to programming**. Therefore, on top of following NDepend rules, programmers must follow [**Uncle Bobs Guide to Clean Code.**](https://www.youtube.com/watch?v=7EmboKQH8lM&list=PLmmYSbUCWJ4x1GO839azG_BBw8rkh-zOj) 
 - This is to enforce 2 goals of DREditor. For more information, you can check out our [**coding guidelines.**](https://dreditor.net/docs/codingguidelines.html) : 
     - _"Programmers should not want to blow their head off reading the code"_. 
     - _"Someone who does not know how to code, should be able to reasonably piece together what your code does"_. 
- **AI Generated or Assisted Contributions**: AI contributions in any capacity are not accepted by DREditor. People found to have done so should be reported to the project maintainer so that they may be blacklisted. Though keep in mind that it is insanely hard to spot AI coding, and it is common for human made code to be detected as AI.
- **Contributions from people who do not sign the CLA**: This is more of just a formality, and to avoid fallout from arguments in which someone may try to remove their contribution regardless of the reason being malicious or not. To sign the CLA, please contact the project maintainer.
